# 批改批次：截止节点统一审核与回信

状态：已实现（服务端 + QQ + 收件箱 + API）。批改仍自动生成草稿，但不逐份回执；到每个作业截止时间统一审核一次。

## 流程

```
邮件到达 → 自动批改草稿（已有）
        ↓ 累积（不立即回信）
作业截止 = 审核节点
        ↓
节点到点 → 收集节点前所有「已登记、已批改、未回信」的提交（跨作业）
        ↓
生成一批 → QQ 通知教师 + 工作台「待办」出现
        ↓
教师通过（可整批）→ 逐封发送回信 → 逐条记录回执
```

节点之后到达的提交进入下一个节点；同一节点只处理一次。

## 操作入口

- QQ 教师私聊：`/batch list`、`通过批改 <批次ID>`、`驳回批改 <批次ID>`；只有一批待审时可省略 ID。
- 工作台：`GET /v1/courses/:id/grading-batches` 查看；`POST .../:batch/approve|reject` 审批。
- 收件箱：`grading` 类型，标题「批改待审核：N 份」。

## 规则

- 回信内容由批改草稿生成：总分 + 各评分点得分与评语。
- 发送失败逐条记录为 `unknown`，**不重发**；成功条数在教师回执里说明。
- 批次状态：`pending` → `approved` / `rejected`；已处理批次不能再次审批。
- 没有可审提交的节点只记节点，不生成空批次。

## 已知限制

- 审批在 QQ 里是异步发送，教师会先收到“开始处理”，完成后收到汇总；大批量（几十人）SMTP 逐封发送会持续较久。
- 暂不支持教师逐条剔除某个学生；需要时先驳回整批，修完草稿再等下一节点。
- 重发与人工补发仍走单封 `POST /mail/messages/:id/reply`。
