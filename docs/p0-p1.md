# DSH 定时任务与 QQ 作业流程

## 定时任务

在工作台「定时任务」为指定计划选择 DSH headless，保存后可立即运行，也可等待北京时间触发。Router 创建任务，DSH 进程获得本次计划的课程工具许可。教师可以允许查教材、读作业、读群消息和已有附件、私信教师或发群文件。每次运行都有独立工作目录，目录按课程与任务定位。

成品可以用 `save_artifact` 登记，或在授权后用 `send_group_file` 同时保存并提交QQ群文件队列。参数使用当前工作目录里的单个文件名。工作台「运行任务」可下载已登记快照与查发送回执，「后台活动」能看到 DSH 工具调用。

当 DSH 调用 `ask_teacher` 时，本任务进入等待。配置的教师在 QQ 引用询问回复后，Router 对应的任务重新入队，DSH 继续先前会话。单独暂停的任务由教师恢复。发群权限按各计划分别设置。

Ubuntu 服务端使用专用 Bubblewrap 启动器和独立 AppArmor 配置。DSH 进程仅挂载运行库、单个任务工作区和该任务的桥接 socket，模型凭据留在内核服务进程。

## 作业提交与延期

作业统一通过**课程邮箱**提交：邮件进入「作业邮箱」，教师核对身份与作业归属后登记为正式提交。私信不再接收作业附件；学生发 `/submit` 只会收到“请通过课程邮箱提交”的提示。

### 学生身份绑定

教师私聊 `/bind 学生QQ号 名单姓名`，一次性把 QQ 与名单姓名绑定。绑定后学生可以私聊查询自己的提交、分数与个人延期，也可以让助教查看自己提交的附件内容。

### 延期

学生直接用日常语言说即可，例如“我生病了，第三次作业能延到 12 月 5 日吗”。答疑 Worker 确认作业与时间后调用 `request_extension` 建立待审批申请；教师在工作台或 DSH 审批。

`/extension` 仍可用（三行格式），但只是兼容别名。旧格式如下：

```text
/extension 作业ID 2026-11-22T22:00:00+08:00
名单姓名
申请原因
```

教师在工作台审批，或在 DSH 用 `ta_coursework` 查看、用 `ta_coursework_file` 读取存档附件，再用 `ta_review_coursework` 审批。可以单独用 `ta_assignment_extension` 读写现有的个别延期。结果经 QQ 私信队列发给原申请人。
