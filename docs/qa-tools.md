# 答疑工具与验收

- 在工作台编辑作业，勾选「允许助教向本课程学生查答这份作业」再保存。旧作业及未勾选的作业不会被答疑工具读取。保存不发群通知；QQ 教师操作、线下登记和登分流程仍照旧。
- 工具只访问任务课程的学生可见作业和已绑定教材。作业详情返回题面、提交要求、截止时间和可读取的题图编号，不返回教师评分标准或学生成绩。可读取同渠道、同课程、同一讨论的明确引用原文或已发答复。
- 安装 Poppler 的 `pdftoppm`（Ubuntu 为 `poppler-utils`），由助教服务的 PATH 提供，或设 `PDF_RENDERER` 指向可执行文件。需要已导入的 `source.pdf`、页数和源 PDF 哈希。默认在官方 `deepseek-flash` 上启用视觉；其它兼容接口确认支持 Chat Completions 工具图像输出后再设置 `MODEL_VISION_ENABLED=true`。缺少渲染器、原 PDF 或视觉能力时，模型收到未读取说明。
- Worker 使用原生只读工具及本轮的 JSON 结束动作。简答默认一条，最多三条；公式走渲染，渲染失败会记录并停下，静默不生成出站消息。半截输出、未完成的工具调用不执行。实际交付由现有专属 LLBot 和 Outbox 执行；若一条发送结果未知，后续分条不发送。
- 多轮读取记录简短检查点并续租；检查点用于诊断，进程中断后重做未完成的只读工作。新的输入、课程修订、取消或作业撤回可使旧结果失效。已确认或结果不明的外部发送不自动重发。

本地验收：`npm run typecheck`，再用 `node --test --test-concurrency=1 tests/*.test.ts`；关键链路使用本机模拟模型接口，不发 QQ。使用真实教材调用原页适配器可验证 Poppler。上线联调应选独立助教测试课程和账号，先保持 `QQ_SEND_ENABLED=false`，确认读工具和交付队列，再单独验证 QQ 实际收图及回执。
