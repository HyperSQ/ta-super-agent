# 跨渠道任务记忆

Router 创建并更新任务身份、目标与授权。任务引擎把具体任务和控制消息关联起来，并在修改目标时保存上一版本的结果和产物引用。TaskRunner 在实际领取任务之后组装交接数据。课程进度、知识资料绑定和任务版本来自该次运行读取的最新记录。

| 交接信息 | 内容 |
|---|---|
| 任务 | 稳定 ID、职责、目标、任务版本与输入版本 |
| 课程 | ID、当前版本、进度、更新时间与来源、教材引用 |
| 输入 | 原始事件、最近输入、入口类型、收件 ID 与附件元数据 |
| 变更 | 最近四次变更的操作、渠道、时间和事件 ID；改写前目标的摘录 |
| 执行状态 | 本版本的阶段或步骤、待答教师问题与关联答复、可用产物引用 |
| 前版内容 | 结果摘录和文件引用；Linux DSH 可按页读取本任务前版正文 |
| 授权 | 回复渠道和计划配置的工具许可。具体工具与外发继续由程序校验。 |

学生个人经历继续通过答疑的记忆服务按身份与渠道检索；成绩、名单和提交情况仍从正式业务接口读取。同一课程的任务也只会收到自身的交接信息。交接数据进入 Worker 输入，近期变更来历可在工作台的活动记录回查。

## 验收

1. 从教师 QQ 发起 `/lesson 准备一致收敛讲义，保留反例`，记录工作台任务编号，等待初稿。
2. 在 DSH 助教会话查询这一课的材料任务，并要求「把这份讲义缩到两页」。核对 DSH 展示的任务与目标后确认。
3. 工作台应看到同一个任务进入新版本；开始执行记录包含原始 QQ 事件和后来的修改事件。旧正文保留为前版材料。
4. 同课有两份材料时，QQ 上说「把刚才那份讲义缩到两页」应询问具体任务。教师可带任务 ID 或用「标题」指定。跨课程读写和过期版本会被接口拒绝。

这一版的跨渠道任务定位入口覆盖教师材料。邮件与 QQ 补件的自动关联、跨渠道学生身份绑定和课程长期记忆仍待接入。

## 教师共享对话

教师的 QQ 私聊、DSH 助教会话和工作台「课程助教」使用同一个课程对话。助教可从近期交流识别同一项工作。QQ 发起的事务可在 DSH 补充信息，并从工作台回确认码。工作台发起、DSH 暂停的材料任务可从 QQ 继续。消息回应留在发起该轮的入口。

QQ 使用服务器验证的教师账号。管理端通过该课程的唯一已授权联系人关联 QQ；没有明确课程联系人时，仅在服务器只配置一位教师 QQ 时关联。如果发现多个可能身份，DSH 和工作台仍共享管理端对话。普通 DSH 会话不会加载助教桥接工具。学生私聊和群聊继续使用各自的学习记忆权限。

工作台显示近 30 条教师对话。Router 和 Worker 取当前事件之前最多 5 轮、有来源的交流与任务引用。任务执行状态、成绩、作业及附件仍通过正式记录读取。切换课程后，对话和延续意图按新课程重新判断。
