## 先用一分钟讲清设计

~~~mermaid
flowchart LR
    QQ["QQ 群与私信"] --> Intake["专属 LLBot 接入<br/>核验群与真实 QQ 身份"]
    Intake --> Thread["定位 Thread<br/>引用续接或新建讨论"]
    Thread --> Router["新问题与教师指令 → Router"]
    Thread -->|"学生续问直接投递"| Engine["Task Engine<br/>订阅、输入、版本和租约"]
    Router --> Engine
    Engine --> Worker["答疑 Worker"]
    Context["课程进度、教材证据<br/>当前讨论和本人相关记忆"] --> Worker
    Worker --> Engine
    Engine --> Outbox["交付队列<br/>核对目标与权限"]
    Outbox -->|"启用外发后"| QQ
    Engine -->|"答疑完成后"| Memory["后台提取学习记忆<br/>保存原文证据和版本"]
    Memory --> Context
    Desktop["教师工作台"] -->|"SSH"| Admin["管理 API"]
    Admin --> Records["课程、作业、评分标准<br/>线下提交记录"]
    Admin --> Engine
    Admin --> Memory
    Records --> Context
~~~

**Thread 是讨论，Task 是要完成的工作。** 学生 A 和学生 B 分别发起问题时，各自的新讨论建立自己的任务。引用已登记的消息追问时，程序按订阅将新输入送到原任务。同一个任务按序处理，多个任务可并发。讨论由引用或私信归属确定，学习记忆则按课程、真实 QQ 和可见渠道检索。

内核在服务器持续运行。事件、任务、订阅、学习记忆和交付状态保存在 SQLite，工作台通过 SSH 访问管理接口。

**教师可以更正系统对任务和讨论的判断。** 修改目标、暂停或收到新输入后，旧运行的版本或租约失效。即使旧模型请求随后返回，程序也拒绝它提交。线程纠错调整消息归属并重建受影响的任务，保留原文、作者和修订历史。

**正式记录与学习记忆用途不同。** 评分标准和交作业情况由业务接口写入。学习记忆来自学生原文，用于调整答疑的解释方式。Router 可以提出动作，实际权限、课程范围和交付对象由程序校验。

## 一、工作台基础操作

### T01 连接、查看课程与断线恢复

1. 打开工作台，输入服务器 IP、SSH 用户名和密码，点 **连接工作台**。首次连接时核对服务器主机指纹再确认。
2. 在左侧 **当前课程** 选择 **数学分析B3（测试）**。点 **总览**，查看教学进度、课程学生和作业数。
3. 点 **断开连接** 后重新连接，确认相同课程仍可读取。

**通过条件**：显示 **SSH 已连接**，两次都能读到服务器上的课程。  
**留证**：总览截图，保留当前课程名和连接状态。若只想先熟悉页面，在登录页点 **暂不连接，体验演示工作台**。演示数据只在当次会话中有效。

### T02 编辑课程和通用评分标准

1. 在测试课程打开 **课程设置**。群号保持为 **<TA_TEST_GROUP_ID>**。
2. 将 **教学进度** 填为 `已讲到一致收敛，下一次介绍一致收敛与连续性的关系。`。将 **助教工作说明** 填为 `先说明适用条件，再给一个例子。`。
3. 在 **通用评分标准** 填入 `满分 10 分。定义 4 分，关键推导 4 分，结论 2 分。同一错误只扣一次。`。在 **课程学生名单** 每行填一个虚构姓名，例如 `演示甲`、`演示乙`、`演示丙`。
4. 点 **保存更改**。回到 **总览** 查看进度，再进入 **课程设置** 核对版本和字段。

**通过条件**：保存的字段可重读，课程版本增加，名单可用于登记。  
**留证**：课程设置的评分标准和保存后的总览。若要演示 **新建课程** 和课程切换，可先在演示工作台操作，现场联调仍使用已绑群、已绑教材的测试课程。

### T03 创建与编辑作业

1. 进入 **作业管理 → 新建**，作业名称填 `【答辩测试】一致收敛练习`。
2. **题目与提交要求** 填 `讨论 fₙ(x)=xⁿ 在 [0,1] 上的逐点极限与一致收敛性，写出判断依据。`。
3. 点 **添加题目图片**，选一张 PNG、JPEG 或 WebP 题图，检查预览。每份作业最多 3 张。填写 **截止时间**，查看 **本次评分标准** 是否带入课程规则，然后点 **保存作业**。
4. 点该条作业的 **编辑**，确认题图、题目、截止时间和评分标准可再次读取。可移除图片、重新添加，再次保存。

**通过条件**：列表仅新增一份测试作业，编辑后仍是同一条。评分标准可持久保存，保存动作不发布群通知。  
**留证**：作业列表、重新打开后的图片预览与评分标准。

### T04 批量登记分数、更正与撤销

1. 进入 **线下登记**，选择 `【答辩测试】一致收敛练习`。分别在 **演示甲、演示乙、演示丙** 的分数格填 `8.5`、`9`、`0`，点 **保存分数**。
2. 把演示甲改为 `9.5` 后保存。在演示乙的行点 **撤销** 并确认。
3. 点 **刷新记录**，重连工作台复查。也可修改作业截止时间再刷新，已录入分数应相同。

**通过条件**：首次保存后有 3 人已录入分数。更正和撤销后有 2 人，演示甲为 9.5、演示丙为 0，演示乙显示 **未评分**。登记只填分数，截止时间不参与判定。  
**留证**：首次保存与更正撤销后的截图。

### T05 查看助教登录状态

1. 打开 **LLBot 登录**，点 **检查状态**，核对助教专属账号和在线状态。
2. 若专属 QQ 自然掉线，点 **刷新二维码**，用该账号的手机 QQ 扫码确认，再点 **检查状态** 或等页面更新。

**通过条件**：在线时显示账号和 **在线**；离线时可刷新登录二维码，重新上线后二维码隐藏。已在线时，可用 T13 中的桌面自动化测试验证二维码分支，无须为了演示主动退出 QQ。  
**留证**：在线截图。离线分支记录刷新及恢复时间，截图中的二维码遮盖后再进入报告。

## 二、用真实 QQ 测答疑和权限

发出测试问题后，在 **运行任务** 点 **刷新**，展开对应条目查看状态和结果。**结果已保存** 表示答疑已生成，QQ 投递按 T12 核对。

### T06 课程群答疑、并发和订阅

1. 普通群成员 A 在测试群用 QQ 的 @ 功能提问 `一致收敛和逐点收敛有什么区别？先给定义。`。
2. 成员 B 随即 @ 助教问 `一致连续和连续有什么区别？`。两人都发送新消息，不引用彼此的问题。
3. 等第一条提问出现在 **运行任务** 后，A 使用 QQ 的 **回复** 功能引用该提问，发送 `对前面的问题，请用 xⁿ 再说明一次。`。即使外发关闭，也可引用原提问来验证续接。外发开启时可另测引用助教答复。
4. 刷新 **运行任务**，确认 A 与 B 的问题分别有结果，A 的追问更新原任务。再发一条既未 @ 助教、也未引用已知消息的普通群消息，确认不生成新答疑任务。

**通过条件**：独立问题分属两个任务，A 的追问继续原讨论，B 的回答不混入 A 的上下文。若只看到两个已完成结果，可证明讨论隔离，不能据此测出同时运行的时间；并发与旧输入拒绝用 T13 的测试复现。  
**留证**：群中两条问题与引用关系、工作台两项任务的结果。需要准确核对 Thread ID 时，见下文“管理记录查询”。

### T07 私信、群白名单和真实身份

1. 普通群成员 A 私信助教 `我想确认一致收敛的定义。`，再私信 `请把量词顺序写出来。`。确认任务继续同课程的私信讨论。若账号有多门可选课程，可用 `/course <TA_TEST_COURSE_ID>`，下一行带问题。
2. 用群外账号私信 `【权限测试】请解释一致收敛。`。工作台不应新增对应任务。仅使用两个账号已经能成功投递到 QQ 的私信来比较，无法发起临时会话时记为 **环境未满足**。
3. 如已有助教所在的另一个测试群，且该群未绑定课程，在那里 @ 助教，核对课程任务没有增加。没有第二群时，用 T13 的白名单测试验证。
4. 用普通群成员账号私信 `/lesson 【学生权限测试】生成一致收敛讲义`。用教师账号发送 `/lesson 【教师权限测试】生成一致收敛讲义`。学生请求不会建立讲义任务，教师请求建立任务后显示 **需要处理**，展开可见讲义 Worker 尚未实现。

**通过条件**：私信按真实群成员资格进入对应课程，课程群范围受限，教师命令按真实 QQ 授权。教师侧的讲义任务用于验证路由和权限。  
**留证**：成员答疑结果、学生命令与教师命令的对照、可选的事件错误。判定权限时优先对照任务或事件记录，不以“没有 QQ 回包”作为唯一证据。

### T08 教材依据和学习记忆

先发 `16.3 T7 的题目是什么？`，核对答复是否引用教材 PDF 第 146 页。只写 `T7` 且缺少可用章节上下文时，应询问章节。再发 `请用公式说明 xⁿ 的逐点极限`，检查 QQ 是否收到排版后的公式图片。

1. 普通群成员 A 在测试群 @ 助教发送 `我经常把一致收敛与逐点收敛的量词顺序弄反。讲一致收敛时我希望先看例子，再看定义。请根据本课程教材解释，有可靠依据再注明出处。`。
2. **运行任务** 出现结果后，打开 **学习记忆**，按 A 的 QQ 或 `一致收敛` 筛选，点 **刷新**。提取在后台完成，模型在证据不足时可以不生成卡片。若出现 **待处理的记忆提取**，先查看错误，修复原因后再点 **重试**。
3. 有卡片时点 **查看与纠正**，展开 **原始依据**，检查原文属于 A。A 在同群发起一个**不引用旧消息**的新 @ 提问，请助教解释同一知识点。比较新结果是否符合 A 的例子优先偏好。B 发同样的新问题用于对照。答案风格只能作为观察，跨线程召回和跨人、跨渠道隔离由 T13 的测试验证。
4. 把 A 的 **后续表现** 修订为 `学生自述容易混淆量词，尚未核验能否独立判断。`，点 **保存并标为教师确认**。重新打开检查版本增加、来源仍可查。完成比较后，可对这条测试卡点 **停用这条记忆**，核对状态为 **已停用**。

**通过条件**：记忆可追溯、可修订、可停用，不能把学生自述直接视为掌握证据。教材答复中的出处需要与实际命中页对照。  
**留证**：任务答复、卡片依据、修订前后版本。服务器本次实际检索 `一致收敛`、`一致连续` 均有命中，运行模式为关键词。向量召回与混合排序另用 T13 验证。

## 三、验证设计中的可控性与恢复

### T09 教师指令、修改、暂停、恢复和取消

1. 用教师 QQ 私信 `请为测试课程新建一道答疑任务，解释一致收敛与逐点收敛的区别。`。在 **运行任务** 核对建立了答疑任务。自然语言由 Router 模型生成建议，可用管理接口直接建立 QA 作为固定流程。
2. 通过管理记录查询取得这条测试任务的 **id**。用教师 QQ 依次发送以下命令，每一步先刷新工作台核对状态，再发下一条。教师命令的执行状态在工作台查看。

~~~text
/task pause <任务ID>
/task revise <任务ID> 只用 xⁿ 的例子解释，最后列出两个量词顺序
/task resume <任务ID>
/task cancel <任务ID>
~~~

**通过条件**：暂停后显示 **已暂停**，暂停时修改目标仍保持暂停，恢复后按新目标生成结果，取消后显示 **已取消**。用普通群成员发送同一控制命令，任务状态不应变化。  
**留证**：任务 ID、命令与状态变化。现场难以保证命令恰在模型运行中到达，T13 能确定性展示运行中打断和旧结果被拒绝。管理 API 的控制操作见 [运行与 API](operations.md#2-管理-api-示例)。

### T10 纠正分错的 Thread

1. 在测试群用同一普通账号发起两条独立 @ 提问，主题分别为 **一致收敛**、**一致连续**。
2. 回复第一条，发送 `【线程纠错测试】我问的是一致连续，为什么要强调同一个 δ？`。当前自动纠错关闭，初次按引用归入第一条讨论。
3. 在管理接口 `GET /v1/threads` 找到这条追问及第二条提问，记下两条的 `eventId`、`threadId`、`revision`。使用下文的“手动迁移测试消息”将追问移至第二条提问的线程。
4. 重新查询 `/v1/threads` 和 `/v1/threads/changes`，刷新 **运行任务**。用 T13 的线程测试复现“收到反馈 → 模型建议 → 程序校验 → 重建任务”。若想用真实模型试一次复核，可通过 `POST /v1/events/<反馈事件ID>/reconsider` 单独触发，记录模型实际给出的保持或迁移结果。

**通过条件**：追问归属改到第二条讨论，原文和作者可追溯，有修订历史。受影响的待发旧答复撤销，任务按纠正后的上下文继续。  
**留证**：迁移前后两条归属记录、修订历史与新答案。已发消息保留原历史。

### T11 持久状态、重复输入和发送异常

1. 让一条测试问答生成结果后关闭工作台，再打开查看任务结果、课程和线下登记仍在。这一操作验证桌面断开后的持久记录。
2. 运行 T13 的 Runtime 测试，核对重复事件只处理一次、旧租约失效后可重新领取、发送结果不明标为 `unknown` 且不自动重发。答辩现场可直接展示对应测试，避免为了复现故障中断运行服务。

**留证**：重连后的记录截图和相关测试名称。区分工作台断开与后端重启恢复。

### T12 真实 QQ 投递与引用答复

服务器已启用 `QQ_SEND_ENABLED`。分别记录群聊和私信的真实投递结果。

1. 检查 **LLBot 登录** 显示在线。
2. 从测试群和普通成员私信各发一个新文字问题。分别确认 QQ 收到答复，并用 QQ 的 **回复** 功能引用答复追加一个问题。
3. 对照 `GET /v1/deliveries` 的状态和外部消息 ID，确认目标为原测试群或原私信发送者。出现 `unknown` 时先在 QQ 核对实际到达情况。私信是否能实际送达还受 QQ 临时会话或好友关系影响。

**通过条件**：对群聊和私信分别判定，收到真实回包且引用后续接原讨论的渠道记为通过。遇到 QQ 投递限制则记录具体限制。  
**留证**：QQ 收件截图和对应的 `sent` 记录。`pending` 表示等待发送，`withdrawn` 表示待发记录已撤销。

### T13 本地可重复验证

在项目根目录用 PowerShell 执行。需要 Node.js 24.15 或更新版本。若依赖尚未安装，先运行 `npm ci` 和 `npm --prefix desktop ci`。

~~~powershell
npm run demo
npm run check
npm run desktop:test
~~~

`demo` 应输出 **2 个独立任务、3 次模拟交付**。自动化测试需允许连接本机临时服务。后端 **78 项**、桌面 **7 项**均通过。

| 现场要解释的机制 | 单独运行的验证命令 |
| --- | --- |
| 并发、订阅、打断、版本校验、租约恢复和未知投递 | `node --test tests/runtime.test.ts` |

### 管理记录查询

工作台的 **运行任务** 可看结果和状态。任务 ID、讨论归属与交付回执通过管理员 API 查询。具备服务器 SSH 访问权限时，可在服务器终端执行以下只读命令。它从配置中读取管理令牌并在请求中使用，输出仅包含指定的记录字段。

~~~bash
cd <TA_SERVER_DIR>
node --env-file=.env --input-type=module <<'JS'
const headers = { authorization: 'Bearer ' + process.env.ADMIN_TOKEN };
const base = 'http://127.0.0.1:' + process.env.PORT;
const courseId = '<TA_TEST_COURSE_ID>';
const get = async (path) => {
  const response = await fetch(base + path, { headers });
  if (!response.ok) throw new Error(path + ' HTTP ' + response.status);
  return response.json();
};
const tasks = (await get('/v1/tasks')).filter(task => task.courseId === courseId);
const taskIds = new Set(tasks.map(task => task.id));
const threads = (await get('/v1/threads')).filter(thread => thread.courseId === courseId);
const deliveries = (await get('/v1/deliveries')).filter(delivery => taskIds.has(delivery.taskId));
console.table(tasks.slice(-12).map(({ id, goal, status, revision }) => ({ id, goal, status, revision })));
console.table(threads.slice(-12).map(({ eventId, text, threadId, revision }) => ({ eventId, text, threadId, revision })));
console.table(deliveries.slice(-12).map(({ taskId, status, externalId, channel }) => ({ taskId, status, externalId, channel: channel.kind, target: channel.target })));
JS
~~~

### 手动迁移测试消息

在服务器终端执行下列命令前，先用上面的查询找到 T10 的两条消息。将四个示例值替换为查询到的消息 ID 和最新归属版本。源是被错误引用的追问，目标是正确讨论的第二条提问。
