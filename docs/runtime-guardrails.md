# 跨跳召回、批处理、监督与退避

状态：P1 的跨跳召回与批处理、P2 的规则型 Watchdog 与瞬态错误退避已实现。订阅扩展按方案推迟到出现第二种真实作用域之后；P0-B 教师收件箱尚未实现，告警暂由只读接口提供。

## 跨跳召回

新增两个只读工具，权限沿用当前课程、渠道、线程归属与 `QATools`：

| 工具 | 作用 | 边界 |
|---|---|---|
| `read_message(eventId)` | 读取本任务线程内的消息，或沿明确引用追溯到两跳 | 同课程、同渠道；线程外消息只能经由引用链进入；他人私聊不可读 |
| `read_more(ref)` | 继续读取本轮上下文被省略的原文 | `ref` 必须是本轮上下文或本条工具返回的；每次 8000 字，返回 `nextRef` |

- 讨论消息超过 1200 字时，`ContextBuilder` 只放前段并给出 `ref`，同时把该引用写入 `run.readRefs`。
- 引用链从本任务输入与原始事件出发，最多两跳；第三跳拒绝。
- 线程归属被纠正后，被移出本线程的消息立即不可读，引用映射随 `moveEvent` 更新。
- 跨课程、跨渠道、其他学生的私聊一律返回 `forbidden` 类别错误，不泄露存在性以外的内容。

## 批处理

- `Router.routeBatch(events)` 按到达顺序逐条处理，已路由的事件跳过，重复调用幂等。
- `Runtime` 增加合并窗口 `TA_BATCH_MS`（默认 `0`，即关闭）。开启后只合并**同课程、同线程**的学生自然语言；教师消息与 `/task`、`/lesson`、`/thread` 命令立即路由。
- 窗口到时，同一批事件在一次路由任务里顺序处理：第一条建任务，其余成为该任务的输入，因此只发生一次模型调用。
- 冲刷批次的那一拍不领取任务，等输入全部进入同一任务后再交给 `TaskRunner`。
- 建议先用 1500–3000 ms 观察同一讨论的重复运行次数与首条响应延迟，再决定是否长期开启；默认关闭以保证部署行为不变。

## 规则型 Watchdog

`src/application/watchdog.ts` 每 15 秒扫描一次，只读不写任务：

| 规则 | 触发条件 | 级别 |
|---|---|---|
| `stalled_task` | `running` 任务超过 `stallMs`（默认 180 秒）没有新活动 | warning |
| `unknown_delivery` | 交付状态为 `unknown` 且任务一分钟内没有被处理 | critical |

- 告警按 `(course, rule, target)` 去重，冷却期默认 600 秒；重复扫描只刷新时间，不新增行。
- 存于 `alerts` 表（迁移 018），`GET /v1/courses/:courseId/alerts?limit=20` 使用管理令牌读取。
- 告警不改任务状态、不重发消息；`unknown` 仍按原有回执流程人工核对。
- P0-B 已落地：告警作为 `alert` 条目并入教师收件箱，同时保留只读接口 [`GET /v1/courses/:courseId/alerts`](inbox.md)。

## 瞬态错误退避

- 只对可安全重放的错误重试：`HTTP 429/5xx`、超时、连接失败、`DomainError('unavailable')`。
- 最多 3 次，间隔 5 秒、20 秒、60 秒；期间任务为 `queued` 并带 `retryAt`，`claim` 跳过未到期任务。
- 次数用尽或永久错误（权限、参数、输出无效、未配置模型）立即 `blocked`，并沿用 P0-A 写一份阻塞汇报。
- 成功提交时清除 `attempts` 与 `retryAt`。
- 外部发送步骤不进入该退避；发送结果未知仍只记录 `unknown`，不自动重发。

## 验收

`tests/task-recall.test.ts`：同线程直读、两跳引用、三跳拒绝、跨课与他人私聊拒绝、线程纠正后失效、截断 ref 与伪造 ref。

`tests/batch-watchdog.test.ts`：`routeBatch` 合并与幂等、Runtime 窗口内不建任务且窗口后合并、停滞告警去重与冷却刷新、未知交付告警、告警接口鉴权与课程隔离、退避三次后 blocked 并写汇报、永久错误立即 blocked、成功后清除退避。

可重复轨迹：

1. 同一线程连发两条学生消息，`TA_BATCH_MS=1500` 下只生成一个任务、两条输入、一次运行。
2. 用一条引用另一线程的消息发问，模型可读被引用原文与它的被引用原文，第三跳返回不可读。
3. 把线程中的一条消息纠正到别的讨论，再次 `read_message` 该消息返回不可读。
4. 制造一次 `HTTP 503` 失败，任务进入 `queued` 且 `retryAt` 在未来；到期后重新领取，第三次失败才 `blocked` 并出现阻塞汇报。
