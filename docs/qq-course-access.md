# 课程群白名单与群成员私信

日期：2026-11-09。

## 规则

- 群内收信和发言都必须属于该课程当前绑定的QQ群。未绑定群时，默认禁止该课程群聊输出。
- 学生私信必须通过专属LLBot查询到他是该课程群成员。姓名、群备注、好友身份和正文中的声明均不授予资格。
- 教师使用TEACHER_QQ_IDS中配置的真实QQ身份，可以私信管理课程；不要求教师自己同时具备学生成员资格。
- 接入、执行模型前、实际私信发送前分别校验；发送群消息前重新核对当前绑定群。课程换群不能使旧任务继续向旧群发言。
- 所有回复绑定真实发信人及任务渠道，模型不能自由填写收件人或切换课程。
- 成员接口故障不会按“允许”处理：入站返回503，尚未发送的回复延后至少5秒再校验；确定已退群则撤销待发回复。
- 不自动加好友、不替学生申请入群，不向群外账号开放课程私信。QQ对临时会话/好友关系的投递限制仍由QQ执行。

## 私信课程选择

只有一门符合资格的课程时，自动进入该课程。后续私信按真实QQ和课程分别保留Thread，不需要每次引用。

同时参加多门课程时，先回复一个由程序生成的选课提示，不调用回答模型，也不提取学习记忆。选课格式：

```text
/course <TA_TEST_COURSE_ID>
```

也可以在下一行附上问题：

```text
/course <TA_TEST_COURSE_ID>
一致收敛与逐点收敛有什么区别？
```

引用先前某课程的私信答复可以定位该课程；其他用户的引用不会借此进入别人的Thread。每次选择仍检查当前成员资格。若原课程资格失效，不会把含混追问自动切换到另一门课，而是提示重新选择。

接口上的courseId只限定候选课程，不授予访问资格；正文/course不能越过这个来源范围。

## 实现

- src/application/services/qq-access.ts：课程选择、成员资格、私信上下文、执行和发送授权。
- src/adapters/qq/membership.ts：通过专属LLBot的get_group_member_list查询成员；每次请求携带no_cache，不持久保存成员白名单。资格准确性依赖LLBot所返回的成员信息。
- src/application/task-engine.ts：课程/渠道/真实作者检查，过期交付拒绝，成员服务故障延后交付。
- src/adapters/qq/llbot.ts：群接入、必须授权的实际发送适配器；低层同步入口不能绕过私信成员检查。
- migrations/005-private-courses.sql：仅保存QQ在某课程中的会话选择，不是QQ/邮箱/姓名绑定表。
- tests/qq-access.test.ts：成员、群外账号、教师身份、多课程、引用、退群、换群、故障、异步竞态及HTTP发送边界。

接口沿用[OneBot 11公开API](https://github.com/botuniverse/onebot-11/blob/master/api/public.md)，执行真实查询时只访问助教专属实例。
