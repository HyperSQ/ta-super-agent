01 · 能力地图：谁在用，能做什么

学生（QQ 群 / 私聊）

  • 群里 @ 助教提问，引用原答复继续追问；发图片问题。
  • 私聊 /assignments 查作业、/extension 申请延期；作业通过课程邮箱提交。
  • 已通教材检索、精确题号、原页核对、公式图、按作业与进度作答。
  • 私聊查询自己的提交次数、迟交、个人延期与线下分数；说一句想延期，助教建待审批申请。
  • 边界未 @ 的群消息只入库不回答；群内自由转发、任意文件上传未接。

教师（QQ / 工作台 / DSH）

  • QQ 一句话建作业、改作业、登记分数、更新进度、维护名单（一次性确认）；说“把 QQ … 绑定到 …”即可绑定学生。
  • 工作台管课程、作业、线下登记、延期、定时任务、学习记忆、邮箱、提交与延期。新增「待办」。
  • DSH 助教会话：本地文件与脚本 + ta_* 工具，发群、改记录需确认卡。
  • 问「本课程还有什么等我决定」由课程计划确定性回答，不调规划模型。

系统自己（按计划/规则）

  • 每周定时备课：原生 Worker 或 Linux DSH 沙箱，产物可发群文件。
  • 答疑完成后异步提取学习记忆；教材检索按课程绑定。
  • Watchdog 每 15 秒扫描停滞任务与未知交付，只告警不改任务。
  • 瞬态模型错误退避重试（5s / 20s / 60s，最多 3 次）。

开发者（可验证）

  • 146 个后端用例、7 个桌面用例；npm run check、npm run desktop:test。
  • 18 个迁移，IF NOT EXISTS 可重复启动；单实例 SQLite。
  • 管理 API + 只读观察接口；所有外发默认受开关控制。
  • 演示模式无需服务器即可走通界面。

02 · 系统全景：一个内核，四个入口

入口连接方式它不做什么
QQ（LLBot）本机 HTTP webhook，令牌/签名校验不直接读数据库、不自己决定发给谁
助教工作台SSH 隧道到 127.0.0.1 管理 API不持有管理令牌、不直连 SQLite
DSH 插件SSH 转发；工具按需连服务器确认卡之前不写业务、不发群
邮箱IMAP / SMTP，经服务端收件服务不自动回信、不替代教师核对

03 · 学生提问：一条消息的完整数据流

数据残留：原始消息（events）、线程归属（event_threads）、任务与输入（tasks / task_inputs）、汇报（task_reports）、交付（deliveries）、过程（activities）。任何一步失败，都不会凭空产生一条“已发送”的消息。

04 · 教师事务：QQ 一句话到正式记录

跨入口一致

  • QQ 发起，DSH 可补字段，工作台可核对。
  • 三者看的是同一条作业与同一个版本。

确认码边界

  • 绑定教师与课程，过期作废。
  • 收件箱与日志都不显示确认码。

不自动群发

  • 保存作业不等于发布通知。
  • 发群是单独动作，要教师确认。

05 · 定时备课：DSH 沙箱里的长任务

隔离手段作用
Bubblewrap + AppArmor只挂载运行库、单个任务工作区和该任务的桥接 socket
按计划授权工具计划里没勾的能力，DSH 调用直接被拒
产物哈希归档同名文件按 SHA-256 留档，教师可下载、可查发送回执
教师答复续跑任务进入 waiting_teacher，教师引用回复后继续同一会话

06 · 邮件收作业：先核对，再批改，最后回信

已经做到

  • 文本与文字层 PDF 的批改草稿，逐评分点带证据。
  • 草稿可编辑；回信走教师确认。
  • 与 QQ 提交共用同一套正式提交记录。

还没做

  • 扫描件 OCR。
  • 自动登分与自动回信。
  • 邮件正文与附件不进入收件箱，也不会进模型摘要。

08 · 状态机与三道校验：旧结果为什么进不来

提交前任务版本 + 输入纪元 + 租约 + 课程版本 + 记忆/作业读取版本，全部匹配才允许写入。
交付领取任务仍完成、版本未变、渠道未换、目标事件属于该任务，否则撤销这条待发记录。
发送前再校验一次目标群与作者；发送结果未知只记 unknown，绝不自动重发。

什么会让旧结果失效

触发程序动作
学生补充新输入输入纪元 +1，旧运行结果拒绝提交，任务重新排队
教师修改目标 / 暂停 / 取消版本 +1，撤销未发交付，旧租约作废
记忆被教师修订依赖该版本记忆的任务失效并重建上下文
作业被修改或撤回读取该作业的任务失效，未发答复撤销
Thread 归属被纠正双侧任务版本 +1，旧结果作废，原文与作者保留

09 · 待办收件箱与建议：教师只看“等我决定”的

隐私处理

  • 草稿与名单的确认码不返回，名单用哈希展示 ID。
  • 邮件只给主题，不给正文、附件、发件人。
  • 学生答疑与作业邮件的汇报只给数量，内容留在受控入口。

建议（只读候选）

  • 四条规则：提交积压、邮件积压、记忆失败、任务停滞。
  • 每条带理由，不建任务、不发消息、不自动执行。
  • 观察一段时间再讨论“自动执行”。

10 · 安全与隐私边界

边界做法
身份教师 QQ 白名单 + 真实 QQ ID；学生不能创建教师任务或执行控制；管理端与 QQ 是两套入口。
渠道群号白名单；私信只能回复真实发信者；任务交付目标由授权固定，模型改不了。
版本任何修改产生新版本；旧运行迟到的结果一律拒收。
外发默认关闭；开启后仍走队列与回执；unknown 不重发；确认码一次性。
注入学生消息、教材、记忆、工具结果都视为资料；权限由程序判定，不靠提示词。
沙箱DSH 用 bwrap + AppArmor；模型密钥留在内核。
审计活动记录按消息串起模型调用、工具与交付；汇报与告警可回查。

11 · 当前边界：已经做到了哪一步

阶段已完成未完成
P0-A任务汇报、课程计划、教师问计划、继续材料任务汇报尚未在工作台单独成页
P0-B七类待办收件箱、工作台「待办」页、隐私去敏只读，动作回原入口
P1跨跳召回（两跳 + 续读）、同线程批处理订阅作用域迁移（等第二种真实用例）
P2规则型 Watchdog、未知交付告警、瞬态错误退避语义级监督、跨设备执行
P3四条只读建议与理由自动执行、一键采纳
仍然明确不做的：学生账号体系、跨渠道身份绑定、群内自由文件识别、扫描件 OCR、自动登分与自动回信、周报、USTC 官方系统填报（缺授权）。
已知限制：单实例 SQLite；日常答疑仍走原生 Worker（未迁到 DSH）；批处理默认关闭，需要 TA_BATCH_MS 显式开启；告警并入收件箱但没有独立告警页。
